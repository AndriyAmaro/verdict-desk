Learn it by breaking it

DashboardJudge pathMarket voicesWitnessesEvidenceLearn

The bounty is a developer-education program, so this page is a short course. Each exercise makes one idea concrete by letting you try to fool the system, and ends with what you should have learned. About twenty minutes in all; all but two need nothing installed. Every position is simulated and no real-money order is ever placed (practice trades use test tokens on Sepolia).

1. Break the hash chain

2 minutes · Dashboard

  1. Press Test the chain. One dossier is edited in a copy held in your tab and the whole chain is verified again.
  2. Press Tamper and re-hash: the edited record now looks valid, but the next one no longer links to it.
  3. Press Rewrite the whole chain: now everything verifies. Look at the head hash.
You should have learned: a hash chain makes a quiet edit loud, but whoever holds the whole chain can rewrite all of it. The only defence is a copy of the head kept somewhere they cannot reach, which is exercise 5.

2. Remove the argument that decided

2 minutes · Cause and effect lab

  1. Pick a LONG or SHORT dossier and look for the red rows: those are the single arguments whose removal flips the verdict.
  2. Pick a dossier where no row is red. Why does it survive the loss of any one argument?
  3. Move the sliders in the policy playground until the rule that fires changes name.
You should have learned: "cause and effect" is not a story told afterwards; it is the weight of each argument against a stated threshold, so you can name the one that mattered.

3. Fool the citation validator

3 minutes · terminal · git clone https://github.com/AndriyAmaro/verdict-desk

  1. Read tests/test_citations.py and run python3 -m unittest tests.test_citations -v.
  2. Add a test with a claim whose number is not in the evidence item it cites. It is refused, with its reason.
  3. Add a claim that cites an id that does not exist. Refused again.
You should have learned: a language model may write the arguments, but it does not get to invent the facts under them: a claim stands only if the exact number appears in the exact item it cites.

4. Be the voices, set your own limit

3 minutes · Market voices

  1. In Which voices earned trust, find a voice whose hit rate is high but whose skill is near zero. Why does "by luck" matter?
  2. In Try it, tick two voices and see whether a position opens. Add voices and the high-conviction box until it does.
  3. Raise the risk limit step by step, then try 30. Switch between rules v4 and v5.
You should have learned: a signal is only as good as its measured track record, hits must be compared with luck, and a risk limit is a ceiling the system owns: the user may lower it, never raise it past 25%.

5. Read a Bitcoin proof yourself

3 minutes · Witnesses

  1. Find a head stamped in a Bitcoin block and note the block number and when it was mined.
  2. Press Check every proof against Bitcoin. Each line is your browser replaying the hash steps and asking two independent explorers.
  3. Look at the newest heads: why are they still pending, and why is that not a problem?
You should have learned: a timestamp is a proof that bytes existed by a time, anchored where nobody here can change it. It says nothing about whether the bytes were true.

6. Attack the verifier

5 minutes · terminal

  1. Run python3 -m verdict_desk battery --trials 300. Note the two attack classes the hash chain alone cannot see.
  2. Copy ledger/ledger.jsonl, change one character in the copy, and run python3 -m verdict_desk --ledger copy.jsonl verify.
  3. Try to design an attack that is not in verdict_desk/battery.py. If one gets through, you have found a real finding: open an issue.
You should have learned: a verifier is only credible if someone tried hard to fool it and wrote the count down, including the attacks it cannot catch alone.

7. Sign only what you can stand behind

3 minutes · Evidence for a lawyer

  1. Pick a dossier. The page re-checks the chain and its hash in your browser, then drafts a declaration.
  2. Go through the draft paragraph by paragraph: which statements could you make truthfully only after running a command yourself?
  3. Read the table above it: why is an OpenTimestamps stamp not an eIDAS qualified time stamp?
You should have learned: authenticating a record and persuading a court of its weight are different things. The technology can make an honest certification possible; it cannot make a record admissible.

A short glossary

Dossier
One decision, frozen: the evidence the agent saw, the arguments for and against, the verdict, and the position it would take.
Hash, and the hash chain
A fingerprint of some bytes. Each dossier carries the fingerprint of the one before it, so changing an old one breaks every link after it.
Canonical JSON (RFC 8785)
One agreed way to write JSON so the same data always gives the same bytes, in Python and in your browser.
Replay
Re-running the rules on the frozen evidence. It either gives the recorded verdict or shows where it differs.
Convergence
Two or more distinct voices taking the same side on the same token. One voice posting five times is still one voice.
Skill above luck
How much more often a voice was right than its own bias and the market's direction would explain, shrunk toward zero on small samples.
Merkle root
The single hash in a Bitcoin block header that commits to every transaction in it; a timestamp proof ends at one.
Anchor
Writing the head of the chain somewhere outside the operator's control: Bitcoin (OpenTimestamps), an Ethereum testnet contract (Chainlink CRE), git history.
