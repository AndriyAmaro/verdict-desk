If a Verdict Desk record reaches you as a file — from a colleague, an email, a screenshot transcription — you should not have to trust whoever sent it, or this site. Paste it below and this page does three independent checks in your own browser.

3. Why each check matters

  • Integrity — the SHA-256 over the record's canonical JSON (RFC 8785) is recomputed here. If it differs from the recorded hash, the file was edited after recording, and nothing below can rescue it.
  • Linkage — the record names the hash before it. This page reads the published ledger and confirms the previous record exists with that hash, so the file is part of a chain rather than a standalone claim.
  • Re-derivation — the arguments stored in the record are fed back through the same policy the ledger was produced with (web/policy.js). If today's rules produce a different action from the recorded one, the record no longer explains itself and you are told so.

Nothing is uploaded. The page has no network access except reading the public ledger file from this site.
